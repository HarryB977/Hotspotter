# v0.1-C: vista 3D, pila de capas, proyectos y trabajo en segundo plano. Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the v0.1 everyday flow. The work is:
- a 3D test view with automatic hotspot fitting;
- a layer stack driving the inspector;
- saving and opening `.hsp` projects with every imported image;
- structure analysis and checks moved off the main thread;
- the deferred v0.1-B minors fixed.

**Architecture:**
- **Pure TS in `packages/core`.** The project zip format, the hotspot matcher/UV mapper and the test-shape generators live here, unit-tested with Vitest.
- **Workers.** A Vite module Worker in `apps/web` runs `analyzeStructure` and `runChecks` on transferred buffers. The store keeps its generation counters and only awaits a promise.
- **3D view.** It uses three.js `WebGLRenderer`. Its textures are the preview atlas read back once per composition (rgba8), not shared GPU textures. This is decision #72 of this plan; the reasons are in Task 10.

**Tech Stack:** TypeScript, React 18.3.1, zustand, Tailwind/shadcn, WebGPU/WGSL engine, three.js **0.170.0** (new), Vitest, Playwright (headless Chrome `--enable-unsafe-webgpu`).

**Spec:** `docs/superpowers/specs/2026-11-11-hotspotter-design.md`, plus `docs/02-architecture.md` (Modelo de documento: `.hsp` = JSON graph + resources, zipped), `docs/05-ui.md` (Vista principal, Vista 3D, Pila), `docs/06-export.md` and `docs/10-roadmap.md` ("Falta para cerrar la v0.1").

Out of scope:
- `.exe` and updates (v0.1-D).
- Undo/redo and the command palette (v0.2).
- Loose specks inside the wEff strip (decision 51) and the Anvil `Can mirror` check (decision 54), which the user verifies by hand.

## Global Constraints

- UI copy in Spanish in `apps/web/src/i18n/es.ts`, in plain words for a non-artist. Code and comments in English.
- Dense dark tool UI (docs/05 "Estilo visual"). The window never scrolls; only side columns scroll (decision 71). No text selection outside editable fields.
- Product rules 1–5 in CLAUDE.md apply. In particular, the 3D view samples the atlas exactly as an engine would: no per-face stretching beyond what the matcher's mapping produces.
- New dependencies: only `three@0.170.0` and `@types/three@0.170.0`, pinned exactly. No zip library: the zip codec is written in core, using the platform `CompressionStream('deflate-raw')` / `DecompressionStream('deflate-raw')`.
- No external network resources at runtime. Lighting uses three's `RoomEnvironment` (procedural). No HDRI files are downloaded or committed.
- `samples/` is never committed. The server stays loopback-only with the Host/Origin checks (R9/R13) and the `X-Hotspotter` header for writes.
- Distances in metres; layout px at reference resolution, top-left origin; material y-up (R5); normals GL.
- Tests:
  - run `npm test` and `npx playwright test --workers=1` from `apps/web`;
  - never end a turn while a run is pending, and never edit files during an e2e run;
  - commit as soon as tests pass, before writing the report.
- Workers must never hold a GPU resource. Only plain typed arrays cross the boundary, transferred, not copied, where the main thread no longer needs them.

## Review Focus

1. **Older or damaged `.hsp` files.** Opening one saved by an older build (doc without newer fields, no mask/substrate entries) or a damaged one (missing image, bad JSON) must migrate through `parseDoc` or fail with one Spanish message. It must leave the current project untouched, never half-loaded. Tested in Task 4 (codec) and Task 5 (store).
2. **Opening a project mid-work.** If a project is opened while a composition, analysis or evaluation is in flight, every stale result is discarded and no texture still bound to an in-flight compose is destroyed. Tested in Task 5.
3. **Worker errors.** If analysis or checks throw inside the Worker, or the Worker dies, the error must reach the existing Spanish error UI. The checks panel must not stay "Comprobando…" forever, and a new request must work afterwards. Tested in Tasks 2 and 3.
4. **Faces no rect fits.** A face no rect fits well, for example a 6 × 0.2 m corridor skirting or a 0.05 m stair nosing, must take a tiling strip when one exists, otherwise the closest rect. It must never get NaN or out-of-[0,1] UVs. Tested in Task 8.
5. **Unsaved changes.** With unsaved changes, Nuevo, Abrir or closing the tab must ask before discarding. Tested in Task 5.

### Task 8: Hotspot matching and UV mapping (core)

**Files:**
- Create: `packages/core/src/fit/match.ts`
- Modify: `packages/core/src/index.ts`
- Test: `packages/core/test/fit.test.ts`

**Interfaces:**
- Consumes: `HotspotLayout` and `HotspotRect`. Rects are in reference px with a top-left origin. The atlas covers `worldWidthM` metres across `widthPx`.
- Produces:

```ts
interface FaceQuad { widthM: number; heightM: number; useOn: 'walls' | 'floors' | 'ceilings' }  // face local axes: u = width (right), v = height (up)
interface HotspotFit { rectId: string; rotated: boolean; mirrorX: boolean; mirrorY: boolean;
  /** UV (0..1, V up, engine convention) of the face corners (0,0) (w,0) (w,h) (0,h). */ uv: [[number, number], [number, number], [number, number], [number, number]];
  /** True when the face is longer than the rect along a tileU/tileV axis and repeats it (uv may exceed 1 along that axis only). */ tiled: boolean;
  score: number }
function matchHotspot(face: FaceQuad, layout: HotspotLayout, rotations: ReadonlyMap<string, boolean>, opts?: { seed?: number }): HotspotFit;
```

  Scoring:
  - Each candidate rect is tried unrotated, and rotated when `allowRotation`. Rects whose `useOn` excludes the face are skipped unless no rect remains.
  - Rect metres come from the reference px.
  - `score = |ln(aspectFace / aspectRect)| + 0.5·|ln(areaFace / areaRect)|`.
  - A `tileU` rect matches any face whose `heightM` is within ±25 % of the rect's metre height, with score `|ln(hFace/hRect)|`, and repeats along u in world metres. `tileV` works the same on the other axis.
  - Ties break on the seeded RNG from `rng.ts`.
  - The mapping is a non-uniform stretch of the face onto the rect, as in Anvil/ProBuilder "fit". It is not world-scale tiling, except along a tiling axis.
  - The UV V axis is flipped from the layout's top-left px: `v = 1 − y/heightPx`.

- [ ] **Step 1: Write the failing tests** on the `walls` preset at 8 m.
  - A 1 × 2 m wall face picks the rect with the closest aspect × area, and its uv corners lie exactly on that rect's corners (V flipped).
  - A rotated pick swaps the rect's axes in the uv.
  - A 6 × 0.2 m face picks a `tileU` strip when the layout has one, with `tiled=true` and u span = 6 / stripWidthM.
  - A 0.05 × 0.05 m face and a 40 × 40 m face still return finite uv inside [0,1] on non-tiled axes (Review Focus 4).
  - A floors face never picks a `walls`-only rect while a `floors` or `any` rect exists.
  - The seed changes ties only.

### Task 10: 3D view

**Files:**
- Create: `apps/web/src/viewport/View3D.tsx`, `apps/web/src/viewport/three/scene.ts`, `apps/web/src/viewport/three/atlasTextures.ts`
- Modify: `apps/web/package.json` (add `three@0.170.0` and `@types/three@0.170.0`), `apps/web/src/state/store.ts`, `apps/web/src/i18n/es.ts`, `docs/09-decisions.md` (#72)
- Test: `apps/web/e2e/view3d.spec.ts`

**Interfaces:**
- Consumes:
  - `buildShape` (Task 9), `matchHotspot` (Task 8) and `readbackRgba8` from engine;
  - the current preview atlas `store.atlas` (baseColor, normal, roughness, metallic, ao, height, wearMask, rectId);
  - `ViewportSplit` (Task 7).
- Produces:
  - Store fields `view3d: { shape: TestShape; mode: 'lit' | ActiveMap | 'rects'; lightAzimuthDeg: number; lightElevationDeg: number; pointFilter: boolean }`. They persist in localStorage, not in the project.
  - `atlasTextures.ts` reads back each map once per new `atlas` identity. The reads are sequential and happen at the preview resolution, which is at most 2048. It builds THREE.DataTexture objects and disposes the previous set. baseColor is in the sRGB colour space; the others are linear. Normal maps use `normalScale (1,-1)` only if three's tangent convention needs it for GL normals; verify with a lit test and record the result.

  Rendering:
  - Each face becomes its own two-triangle mesh with uv from `matchHotspot` and a shared `MeshStandardMaterial` using map, normalMap, roughnessMap (G), metalnessMap (B) and aoMap.
  - Rough, metal and AO are separate textures, sampled through a small `onBeforeCompile` channel remap. The alternative is to pack them on the CPU into one ORM texture; that is the recommended option, and it is one readback per map anyway.
  - Tiled faces use `RepeatWrapping` on the tiled axis. Otherwise wrapping is `ClampToEdge`.
  - Environment: `RoomEnvironment` through `PMREMGenerator`, plus one `DirectionalLight` driven by azimuth and elevation.
  - `OrbitControls` provide the camera.

  Modes:
  - lit;
  - a single map shown unlit through `MeshBasicMaterial`;
  - `rects`: lit, plus `LineSegments` outlining each face's matched rect borders projected on the face, and a hover tooltip with the rect id.

  The point filter switches textures to `NearestFilter`.

  The toolbar sits inside the pane: shape Select, mode Select, light azimuth and elevation, point filter, and "Encajar vista". Everything is disposed on unmount and on atlas change.

  **Decision #72 (Constructor).** The 3D view reads the preview atlas back to the CPU once per composition and renders with WebGL. It does not share WebGPU textures, because three 0.170's WebGPU renderer cannot adopt our existing `GPUDevice`'s textures without a second device. The cost is one rgba8 readback per map per composition, at most 2048², which is about 16 MiB per map, done in sequence.
