# Hotspotter v0.1-B · Estructura, desgaste realista y comprobaciones · Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** El atlas deja de tener solo ranuras. La herramienta deduce la estructura del material (periodo, piezas, juntas) y orienta el material según cada rectángulo. Después esculpe un desgaste de borde realista sobre un único campo de altura: macro, pieza, fractura y micro, con sustrato, máscara B/N, suciedad y escorrentía. Por último valida el resultado con comprobaciones automáticas, que se ven en la UI y antes de exportar. Incluye también los dos pendientes que encontró el usuario: importar archivos sueltos (añadir o reemplazar) y la orientación del material.

**Architecture:**
- **Análisis de estructura:** TS puro en `packages/core`, sobre los mapas reducidos a ≤ 512 px. Produce mapas de pieza y de distancia a junta, que se suben a la GPU.
- **Desgaste:** nuevas pasadas WGSL en `packages/engine`. La pérdida se calcula con celdas de Voronoi, fBm y la distancia al borde. Después, la distancia al contorno de la pérdida por jump flooding, el compuesto de altura y por último el compuesto de color. Normal y AO salen siempre del campo de altura final.
- **Comprobaciones:** TS puro en `packages/core`, sobre una composición de evaluación leída de la GPU a 2048 px.
- **Documento:** el grafo gana los nodos `structure`, `wear` y `dirt` y sigue siendo una cadena lineal.

**Tech Stack:** el mismo que la v0.1-A (Node 22, npm workspaces, TypeScript 5.6.3, Vitest 2.1.9, Playwright 1.49.1, Vite 5.4.21, React 18.3.1, Fastify 5.12.7, WebGPU/WGSL). Sin dependencias nuevas.

**Spec:** `docs/superpowers/specs/2026-11-11-hotspotter-design.md` y lo que enlaza. Este plan implementa, sobre todo:
- `docs/03-material-and-layout.md`: importación, análisis de estructura, escala y proporciones con orientación.
- `docs/04-wear.md`: principios, modelo, sustrato, revelado en zona, las familias de la v0.1, "más allá del borde" básico y comprobaciones.
- `docs/10-roadmap.md`: la fila v0.1 y la sección "Pendiente tras probar la v0.1-A".
- `docs/11-test-bench.md`: el criterio de aceptación.
- Decisiones R1–R16 de `docs/09-decisions.md`, que son vinculantes.

Quedan fuera y van a planes siguientes: la pila de capas, el inspector reorganizado y la vista 3D (v0.1-C); el `.exe` y las actualizaciones (v0.1-D); los estilos estilizado y pixel art, el layout manual, las bandas, las variantes, las capas de sustrato (pintura → imprimación → metal), la familia "deshilachado" con opacidad, la corrección automática de islas y las comprobaciones de mip, saltos y pixel art (v0.2).

## Global Constraints

- Las restricciones globales de la v0.1-A siguen en vigor. Están en `docs/superpowers/plans/2026-11-11-v0.1a-foundations.md`, sección Global Constraints: unidades internas en metros, layout en px de referencia con origen arriba a la izquierda, normal interna GL, `createRng(seed)` para todo lo aleatorio, textos de UI en `apps/web/src/i18n/es.ts`, `samples/` fuera de git y tests que se saltan si falta.
- **Regla dura de proporciones:** misma escala del mundo, arranque en junta y nada estirado. Con un material girado 90°, el periodo efectivo en los ejes del atlas se intercambia: el periodo X del material pasa al eje Y del atlas y viceversa.
- **Un único campo de altura (CLAUDE.md, regla 2):** todo el daño resta de `height`. `normal` sale del Sobel de la altura macro (R15) combinado con la normal de detalle, que se desvanece donde hay pérdida. `ao` sale de la altura multiplicado por el AO del material. Ningún mapa se pinta aparte.
- **Detalle en unidades del mundo:** todos los ruidos, celdas y anchos de daño se definen en metros, con coordenadas locales del rectángulo más un desplazamiento por rectángulo derivado de la seed. Preview y export muestran lo mismo a distinta resolución.
- **Determinismo:** el hash de GPU es PCG (`pcg3d` sobre u32). La seed del daño entra como u32 en los Params.
- **Límites de WebGPU:** como mucho 4 storage textures de escritura por etapa. Hay que partir las pasadas para respetarlo, como ya hace `compose.wgsl`.
- **Params WGSL compartido:** después de la Task 1, el struct `Params` vive en un único archivo `shaders/common.wgsl`, que se antepone a cada módulo. Su empaquetado TS vive en `src/params.ts`. Prohibido redeclararlo en otros sitios.
- **Valores por defecto del desgaste** (rango entre paréntesis):

  | Parámetro | Valor | Rango |
  |---|---|---|
  | `intensity` | 0.5 | 0–1 |
  | `widthM` | 0.04 | |
  | `minEdgeM` | 0.004 | |
  | `sizeM` | 0.03 | |
  | `depthM` | 0.006 | |
  | `bandM` | 0.006 | |
  | `microM` | 0.0005 | |
  | `pieceBias` | 0.7 | |
  | `edgeTone` | 0.3 | |
  | `mask.strength` | 1 | |
  | `mask.invert` | false | |

  Valores por defecto de la suciedad: `cavity` 0.4, `runoff` 0.3, `runoffLengthM` 0.4, `tint` [0.25, 0.22, 0.18].
- **Máscara B/N:** blanco = más daño (`invert` lo da la vuelta). Se aplica en UV del atlas completo.
- **Ancho efectivo del daño en un rectángulo:** `min(widthM, 0.33 · min(w, h) del rect en metros)`. Así los trims finos no se los come el desgaste.
- **Familias de la v0.1:** `brittle` (rotura frágil), `chipping` (desconchado), `splinter` (astillado), `erosion` (erosión), `dent` (abolladura y abrasión, sin pérdida de capa) y `edgeOnly` (solo cantos). El deshilachado queda para la v0.2.
- **Composición de evaluación de las comprobaciones:** 2048 px, o la resolución del preview si es mayor.

## Review Focus

1. **Material sin mapa de altura** (solo albedo): el análisis de estructura usa la luminancia invertida del albedo y el desgaste funciona como material continuo, sin errores. Tests en la Task 4 y la Task 8.
2. **Material direccional girado en un rect cuyo tamaño no es múltiplo del periodo girado:** el aviso de proporción usa el periodo intercambiado, no el original. Test en la Task 2.
3. **Trims finos** (rect de 6 cm de alto): el daño no supera un tercio del lado menor y el rect no queda "comido". Test en la Task 8.
4. **Añadir mapas a un material ya cargado:** conserva layout, colocación y desgaste (el documento no se resetea), y solo cambia la textura afectada. Test en la Task 3.
5. **Independencia de resolución:** la fracción de píxeles con pérdida en una composición a 1024 y a 2048 difiere menos de 3 puntos porcentuales, con los mismos parámetros. Test en la Task 8.

Algoritmo por píxel de un rect. Coordenadas locales en metros, con desplazamiento por rect `hash(rectIndex, seed) · 100 m`:

```
e      = distance to the visible rect edge (m), from the shrunk edge (Task 1)
wEff   = min(widthM, 0.33 * min(rectW_m, rectH_m))
pEdge  = intensity * (1 - smoothstep(0, wEff, e))                    // damage potential
pMask  = mask ? mix(1, maskValue(inverted?), strength) : 1
j      = jointDistM at this pixel; pid = pieceId
pPiece = mix(1, (1 - smoothstep(0, sizeM, j)) * (0.5 + hash(pid, seed)), pieceBias * hasPieces)
P      = clamp(pEdge * pMask * pPiece, 0, 1)
q      = warp(local, 0.3*sizeM, seed)
cellV  = voronoi(q / sizeM, anisotropy along grainAxis, seed); cellHash = hash(cellV.cell, pid, seed)
fbmV   = fbm(q / sizeM, 5, seed)
s      = mix(fbmV, cellHash, cellMix)                                 // shape field
lost   = s < P  ||  e < minEdgeM * (1 + 0.6 * fbm(q / (0.5*sizeM)))   // guaranteed rim, never narrower than minEdgeM
loss.r = lost && family.loses ? 1 : 0   (dent/edgeOnly: 0, but G still carries dent depth for dent)
loss.g = depthM * (0.5 + 0.5 * fbm(q / sizeM * 2)) quantized to `steps` levels when steps > 0; dent: depthM * P * 0.5
```
